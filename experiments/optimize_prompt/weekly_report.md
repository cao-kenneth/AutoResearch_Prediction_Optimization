# Weekly Project Report: AutoResearch Prompt Optimization

This week I created a first experiment specification, now archived as `optimize_prompt.md`, for an AutoResearch experiment that uses an LLM agent to improve its own probabilistic forecasting prompt. The project task is to predict whether binary forecasting questions resolve Yes, using only information available as of each forecast date. The evaluation metric is Brier score, so lower scores mean better calibrated probabilities. The specification defines the allowed scope of the agent: it may only revise `prompt.txt`, while the dataset, model runner, parsing logic, and evaluation code stay fixed. It also defines a three-iteration run budget, the required output format, logging rules, and stop condition.

I completed and logged three dry-run optimization experiments. The baseline valid prediction file had a Brier score of about `0.158942`. Run 1 produced the best result, with Brier `0.140731` across 67 valid rows. Run 2 worsened to `0.151896`, so that prompt should be rejected. Run 3 improved relative to the baseline but did not beat Run 1, with Brier `0.141570` across 66 valid rows and one failed parse. All three runs are logged under `outputs/run_001/`, `outputs/run_002/`, and `outputs/run_003/` relative to this experiment folder, each containing the prompt, predictions, and metrics.

The agent did well at identifying a useful general direction for prompt improvement. The best prompt added clearer calibration guidance: start from an outside-view base rate, adjust for specific evidence and deadlines, treat ambiguous resolution criteria as uncertainty, avoid counting near-misses as success, and reserve extreme probabilities for outcomes that are close to certain. This produced a meaningful improvement over the baseline. The agent also kept the forecast output mostly parseable, with all rows parsed successfully in runs 1 and 2.

The agent did badly when it overcorrected from previous errors. Later prompts became more cautious, but that caution sometimes pushed probabilities too far toward No on events that did resolve Yes. Several of the largest errors came from underestimating high-impact political or conflict events, such as the Israel-Iran direct conflict deaths question, WHO PHEIC declaration, and Biden veto question. The agent also struggled with questions where the resolution depended on exact wording, timing, or whether a partial real-world development counted. Run 3 introduced one parsing failure, showing that the output format constraint is still fragile.

The most common failure modes so far are: overconfidence on ambiguous No outcomes, excessive conservatism on rare-but-real Yes outcomes, misreading exact resolution criteria, confusing current evidence with evidence that satisfies the final resolution date, relying too much on plausible narratives instead of decomposed probabilities, and occasional formatting/parsing failures. The next step should be to keep the Run 1 prompt as the current best prompt, add more explicit checks for resolution wording and deadline mechanics, and evaluate on the reserved holdout set only after the prompt-selection process is finalized.
